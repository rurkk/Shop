# Правила разработки Shop

На этапе разработки, до запуска для клиентов, действуют следующие правила.

- Не добавляйте фолбэки. Если основной сценарий не может продолжиться, обработайте ошибку явно.
- Не поддерживайте прежние контракты и форматы ради обратной совместимости. При изменении API, конфигурации или схемы БД обновляйте затронутый код, тесты и документацию в той же доработке. Несовместимые локальные тестовые данные можно пересоздать.
- При выкладке релиза на сервер допустим временный простой. Для обновления можно останавливать и перезапускать сервисы.

Пересмотрите эти правила перед запуском для реальных клиентов.

Требования к продукту и архитектуре описаны в [docs/requirements.md](docs/requirements.md).
